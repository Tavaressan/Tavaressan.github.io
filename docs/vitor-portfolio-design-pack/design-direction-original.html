Kaze Tachinu
Design Direction — Portfolio de Vitor Tavares
A well-organized drafting table: precise, warm, purposeful.

Mesa de trabalho de engenheiro — cada instrumento no lugar, luz quente de tarde, papel que convida a riscar. Nada decorativo; tudo que está ali trabalha.

O design traduz a atmosfera de Kaze Tachinu para a web sem fantasiar o filme — sem bordas de aquarela, sem texturas de papel forçadas. O que entra são as cores (terracota, cinza-azulado, tons de papel envelhecido), o ritmo (respiro generoso, proporções equilibradas) e a atitude (precisão de engenheiro com sensibilidade de artesão). O chibi e os GIFs são os únicos elementos que citam o filme diretamente — o resto da estética existe por si.

02 — Tipo

Tipografia

EB Garamond para display — a serifa europeia com traços afiados que evoca a tipografia entre-guerras (o mundo que Jiro habitava). Não é uma fonte fantasiada de "vintage"; é um revival preciso do Garamond barroco que funciona naturalmente em contexto editorial moderno. Source Sans 3 para corpo — limpa, técnica, desenhada para leitura em tela, com um DNA de engenharia que complementa a serifa sem competir. JetBrains Mono para código.

Escala tipográfica — Major Third (1.25)

Progressão: 0.6875 → 0.875 → 1 → 1.25 → 1.563 → 1.953 → 2.441 → 3.052 rem. A proporção 1.25 é contida o suficiente para não criar saltos dramáticos, mas dá hierarquia clara entre os níveis. O H1 fica grande sem ser agressivo.

Páginas de projeto ou omitir. 6 MB é muito pesado para a home. Duas opções: usar apenas em páginas individuais de projeto (lazy-loaded), ou extrair um frame estático e abandonar a animação. Se usado, fazer crop/mask para mostrar só mãos e mesa.

Performance: Os 4 GIFs somam ~15.7 MB. Na home, usar no máximo 2 (prairie + sketching = 5.7 MB). Os outros ficam para páginas internas ou são convertidos a frames estáticos. Cada GIF deve ter loading="lazy" e, idealmente, um <picture> com poster/frame estático para o primeiro paint.

Tratamento visual dos GIFs

Todos os GIFs recebem o mesmo tratamento para manter coerência:

/* Tratamento padrão para GIFs do filme */ .film-gif { filter: saturate(0.85) sepia(0.08); border-radius: var(--radius); opacity: 0.9; mix-blend-mode: multiply; /* só no light theme */ } /* No dark theme, multiply não funciona — usar normal */ @media (prefers-color-scheme: dark) { .film-gif { mix-blend-mode: normal; opacity: 0.7; filter: saturate(0.75) brightness(0.85); } }

Chibi — Vitor como Jiro Horikoshi

O chibi é o único elemento abertamente lúdico do portfólio. Essa unicidade é o que faz ele funcionar — num contexto de design sério e preciso, a ilustração chibi humaniza sem infantilizar. Se houvesse outros elementos "divertidos", o chibi perderia impacto.

Posicionamento

Posição primária: hero section, à direita do texto, deslocado como um esboço preso na prancheta. Tamanho ~200–280px. Sem moldura, sem card, sem sombra exagerada — ele descansa sobre o papel, não flutua num pedestal de vidro.

Posições secundárias (opcionais): página 404 (Jiro chibi perdido), estado de loading (Jiro desenhando), ou um aceno pequeno no footer. Nunca mais de uma aparição por página.

Pendência: O chibi não está no repositório ainda (assets/images/ contém apenas os 4 GIFs). Se a ilustração já existe, adicioná-la. Se ainda será criada: manter o estilo visual alinhado com a paleta do portfólio — traços limpos, cores que conversem com o terracota e o creme. Evitar outline preto pesado que destoe do tom suave do design.
05 — Tensões

Tensões e trade-offs

Nenhum design coeso elimina tensões — ele as resolve deliberadamente. Estas são as que mapeei entre as escolhas acima:

Refinamento vs. credibilidade técnica

EB Garamond + paleta creme cria uma atmosfera editorial, quase literária. Para recrutadores de software, há o risco de parecer "bonito mas faz o quê?". A serifa pode sugerir design/editorial mais do que engenharia.

Resolução: o conteúdo carrega a voz técnica. Tags de tecnologia em mono, código inline, descrições de projeto com vocabulário preciso ("MQTT telemetry pipeline", não "innovative solution"). O shell visual diz "eu me importo com craft"; o texto diz "eu entrego sistemas".
Estética de época vs. web moderna

A inspiração nos anos 1920–30 pode descambar para fantasia: bordas de aquarela, texturas forçadas, ornamentos art déco. Esse caminho transforma o portfólio num tributo ao filme em vez de num portfólio de desenvolvedor.

Resolução: a referência ao filme entra por canais controlados — cores, proporções, e os GIFs/chibi que citam diretamente. O layout, a tipografia responsiva e a interação são contemporâneos. Ninguém precisa saber que o terracota veio de um telhado do Japão dos anos 30; ele só precisa funcionar.
Peso dos GIFs vs. performance

15.7 MB de GIFs vs. Lighthouse performance. Usar todos destrói o score; não usar nenhum perde a conexão visual com o filme.

Resolução: máximo 2 GIFs na home (lazy-loaded, com poster estático), restante em páginas internas. O GIF de 8.2 MB provavelmente vira frame estático. Performance é requisito, não preferência — aceitar o trade-off e otimizar.
Chibi vs. profissionalismo

Uma ilustração chibi num portfólio de desenvolvedor é uma escolha corajosa. Pode ler como "personalidade" ou como "imaturo", dependendo da execução.

Resolução: o chibi funciona porque é singular. O design ao redor é sério, preciso, adulto. O contraste é intencional — ele mostra que o desenvolvedor tem personalidade e não se leva a sério demais, sem comprometer a competência. Tamanho contido (~250px), uma aparição por página, sem bordas lúdicas ao redor.
Dark theme — identidade vs. inversão

A estética do filme é fundamentalmente "quente e clara" — o dark theme não pode ser uma inversão ingênua senão perde toda a identidade visual.

Resolução: o dark theme tem sua própria narrativa cinematográfica — as cenas noturnas do filme (hotel, oficina). Fundo azul-carvão (não marrom), texto creme (luz de lamparina), acentos aquecidos. Funciona como um capítulo diferente do mesmo filme, não como o filme em negativo.
horizon como label de tecnologia vs. contraste

O azul-horizonte (#6F8D9E) no light theme tem ratio 3.5:1 — passa para texto grande mas falha para texto pequeno. E é justamente em texto pequeno (eyebrows, tags) que ele aparece mais.

Resolução: usar horizon como cor de texto somente em eyebrows (que são uppercase com tracking aberto, funcionando visualmente como "grande" mesmo em fonte pequena) e nunca como cor única de link funcional. Para informação crítica em tamanho pequeno, usar ink-2. No dark theme, #8AAABB passa AA para tudo.

07 — Próximos passos

Decisões pendentes

Para resolver antes de implementar

CSS framework: Os tokens acima funcionam com CSS puro (custom properties), Tailwind (via theme.extend), ou CSS Modules. A escolha depende da preferência de DX e do que o design final exigir em termos de responsividade e estados. A recomendação deste guia: CSS Modules com custom properties — Tailwind adiciona abstração desnecessária quando o design system já está mapeado.

Chibi: Se ainda não foi criada, a ilustração precisa de: traços limpos (não outline pesado), paleta compatível com o terracota/creme, expressão que transmita "concentrado e curioso" (o Jiro de Kaze Tachinu), formato PNG ou SVG com transparência.

GIF writing_desk_closeup_char.gif: Decidir entre extrair frame estático ou usar somente em páginas internas. Os 8.2 MB tornam impraticável para a home.

Favicon: Uma opção coerente: silhueta de óculos redondos (referência ao Jiro) em terracota sobre transparente, em SVG. Simples, reconhecível em 16×16.
